# Local Preview and Pre-Submit Checks

This documentation site is built with Docusaurus and managed with `yarn`. Run a local preview and both pre-submit checks before opening a pull request.

## 1. Environment setup

### 1.1 Git and the source repository

Both local preview and pre-submit checks read the repository's `.git` history. Clone the repository with `git clone` rather than downloading a source ZIP archive, which lacks `.git` metadata and causes preview and build commands to fail.

1. Install Git and verify that it is available:

```bash
git --version
```

2. Clone the repository and enter the project directory:

```bash
git clone https://github.com/lumina-layer-studio/Lumina-Studio-Wiki.git
cd Lumina-Studio-Wiki
```

### 1.2 Node.js and Corepack

You need Node.js 20 or later and Corepack. Corepack is bundled with Node.js 14.19.0 through 24.x, and is no longer included starting with Node.js 25.

If `corepack` is not found (for example on Node.js 25 or later), install it globally first (see the [official Corepack installation guide](https://github.com/nodejs/corepack#how-to-install)):

```bash
npm install -g corepack
```

Enable Corepack:

```bash
corepack enable
```

Then install project dependencies:

```bash
yarn install --immutable
```

The repository pins the exact Yarn 4 version specified in `package.json`.

## 2. Local preview

`yarn start` launches the Chinese site by default:

```bash
yarn start
```

To preview the English site, pass the `--locale en` flag:

```bash
yarn start --locale en
```

Chinese and English build separately and share the same default port, so **only one locale can run at a time**. Press `Ctrl+C` to stop the active dev server before starting the other locale.

## 3. Pre-submit checks

Run both checks in order before committing:

```bash
yarn typecheck
yarn build
```

## 4. Directory and file conventions

- Chinese docs live in `docs/`; English docs live in `i18n/en/docusaurus-plugin-content-docs/current/`.
- Each tutorial lives in its own directory, with the `.mdx` filename matching the directory name and images placed under `assets/`.

Example:

```
docs/tutorials/example/example.mdx
docs/tutorials/example/assets/step-01.webp
```

## 5. Writing conventions

- Use standard Docusaurus Markdown/MDX features only; do not introduce custom image or path components in MDX bodies.
- Do not add `import` statements inside MDX files.
- Reference local images with relative `require` paths inside the page directory:

```jsx
<img src={require('./assets/step-01.webp').default} alt="Step one" />
```
