# Exhaustive Cache Density

A material profile enumerates the layer recipes reachable with your selected filaments and layer count, then indexes their predicted colors in a 3D Lab grid. **Exhaustive Cache Density** sets the resolution of that grid—finer grids keep closely spaced colors with distinct recipes from colliding in the same cell.

  alt="Exhaustive cache density settings"

## Resolution tiers

Available tiers are `64³`, `128³`, `256³`, `512³`, `1024³`, and `2048³`. When custom exhaustive density is turned off, builds default to `64³`.

Higher tiers preserve more candidate recipes by reducing grid collisions, which helps when a material profile requires fine tonal separation. Overall gamut and color accuracy still depend on the underlying optical measurements of your filaments.

## Cache storage and resource budgets

The cache uses sparse storage, saving only physically reachable recipes rather than allocating every cell of the 3D grid. Each tier writes its own cache file, so switching tiers leaves existing caches at other resolutions intact.

Builds stay within automatic resource budgets:

- Small recipe spaces run in exact mode.
- Larger combinations check estimated memory usage and total recipe count beforehand.
- If a build exceeds the active safety budget, it stops cleanly and prompts you to lower the filament or layer count.

Building a new tier for the first time takes noticeably longer than loading a saved cache, and color-lookup time increases slightly at higher densities.

:::note[Solver scope]
This setting applies only to the material-profile solver. Traditional LUTs read their existing measured colors and recipes directly and do not use this grid density.
:::
