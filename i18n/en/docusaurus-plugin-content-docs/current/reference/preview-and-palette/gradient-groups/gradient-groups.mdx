# Gradient Groups and Region Processing

When a smooth gradient is matched to a finite set of filaments, subtle transitions can split into visible stepped bands. **Gradient groups (banding)** detects those bands automatically and provides whole-group and spatial-region tools to recolor, flatten, or locally re-quantize them.

The panel appears when all three conditions are met:

1. The color source is [Material Archive](../../converter-basic/material-archive-source/material-archive-source.mdx).
2. The current image has a completed preview.
3. At least one qualifying gradient group is detected.

When no banding group is found, the panel stays hidden. Legacy LUT and Inferred LUT modes do not run gradient-group detection.

## How smooth gradients are detected

Lumina compares the quantized source image against the material-matched preview. A color boundary joins a gradient group only when the source artwork transitions smoothly across that edge while the matched preview steps from one material color to another. Detection uses the following fixed thresholds:

| Condition | Fixed threshold | Purpose |
| --- | ---: | --- |
| Median source color difference along a boundary | ΔE no greater than 8 | Preserves intentional crisp edges in the artwork |
| Shared boundary between two material colors | At least 15 pixels | Ignores brief contact and isolated noise |
| Coverage of each material color | At least 30 pixels | Excludes negligible stray colors |
| Maximum color difference within one group | ΔE no greater than 30 | Stops nearby shades from chaining into a different hue |
| Expandable connected region | At least 500 pixels, four-way connectivity | Filters out tiny isolated fragments |

Groups are listed from largest to smallest pixel area. Within each group, the material color covering the most pixels becomes its **representative color**, which **Flatten** uses as the fill target. Each row also displays the number of matched colors in the group and their combined pixel count.

## Select all vs. Select region

**Select all** loads every matched color in the group into [All mode](../selection-modes/selection-modes.mdx) and highlights them on the 2D preview. Picking a replacement color then updates every occurrence of those matched colors across the entire image, including any unrelated elements that share the same matched color.

Click **Expand regions** to list each connected area within the group. **Select region** displays the colors inside that specific area and restricts both the highlight and any subsequent replacement to the region's exact pixel mask, leaving matching colors elsewhere in the image untouched.

## Flattening

| Action | Scope | Fill color |
| --- | --- | --- |
| Flatten all gradients | Matched colors in all detected groups | Each group's representative color |
| Flatten (group row) | Exact spatial mask of that group | The group's representative color |
| Flatten (region row) | Exact pixel mask of that region | The parent group's representative color |
| Merge flatten | Two or more checked regions in one group | Most frequent color across the checked regions |

**Flatten all gradients** and [Auto-replace Gradient Banding](../../settings-import-export/auto-gradient-replacement/auto-gradient-replacement.mdx) apply whole-image color remaps: they preserve any manual remaps already in place and map each group's remaining colors to its representative color across the entire canvas.

Group-row **Flatten**, region-row **Flatten**, and **Merge flatten** apply spatial masks so edits stay strictly inside the targeted area. Use the region checkboxes to build a batch list within one group (checking a box does not highlight the canvas, and checking a region in a different group clears the previous selection).

Spatial edits immediately refresh the 2D and 3D previews; regenerate layer views and 3MF files before exporting. Because spatial masks are stored separately from standard color-remap undo steps, run **Preview** again whenever you want to return to the initial matched result.

## Region re-quantization

**Re-quantize** builds a dedicated local palette for the selected region and re-matches it through the active material solver, preserving soft shading transitions while collapsing dense alternating bands.

<img
  src={require('./assets/03-requantize-dialog.webp').default}
  alt="Region re-quantisation dialog with a range of 12 to 256 colours"
/>

- **Range:** **12–256**, defaulting to **64**.
- **Effect:** Higher values retain finer tonal steps; lower values produce a flatter, more uniform transition.
- **Single vs. batch:** Clicking **Re-quantize** on a region row processes only that region without clearing your checked batch list. Clicking **Batch re-quantize** processes all checked regions and clears the checkboxes once complete.
- **Local solving:** Each region generates its own local palette before material matching, and the gradient-group list refreshes automatically afterward.

## Highlight inspection

Click the eye icon on any group or region row to open a read-only cyan mask preview showing the exact pixels included: group-level masks highlight matching colors across the full image, while region-level masks show that region's exact spatial mask. Opening or closing this preview leaves your active selection, main preview, and edit history unchanged.

## Working with automatic replacement

**Auto-replace Gradient Banding** in Settings is off by default. When enabled, every Material Archive preview that detects gradient groups automatically applies the same representative-color remap as **Flatten all gradients** and displays a status notice at the top of the panel so you can still inspect detected groups. When turned off, all manual actions in the panel remain available.
