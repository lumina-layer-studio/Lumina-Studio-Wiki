# Report a bug and diagnostic information

When you run into a generation error, unexpected preview, or broken workflow, open **Report a bug** from the top bar. Lumina packages diagnostic data from your active task and sends it directly to the official issue-collection service—no personal sending email account required.

## Reproduce the issue before opening the form

Keep the affected artwork, recipe, and settings active, trigger the issue once, and then open the form so it captures the exact session state. If you swap artwork or repeat actions while the form is open, use its recollection button to refresh the captured context.

In your description, include:

1. Input format and color source (for example, SVG with a material archive).
2. Exact steps taken and the step where things went wrong.
3. Expected result versus what actually happened.
4. Whether the issue occurs every time or only with a specific file.

Contact email is optional and lets maintainers follow up with you. You can also attach PNG, JPG, WebP, or GIF screenshots; adjust the file if the form flags a size or format limit.

## What may be attached

Depending on your active session, a report can bundle conversion parameters, device selections, recent actions, error logs, and available source images, SVGs, meshes, LUTs, material archives, and generated outputs. Included files reflect whatever is currently loaded in the session.

Developers use these files to reproduce the fault. Before sending, check the attachment summary to make sure you have permission to share any client artwork or proprietary models, and check screenshots for account names, notifications, or other private details.

## Ticket ID and upload status

After submitting, note your ticket ID and watch the upload status until it finishes:

| Status | Meaning and next step |
| --- | --- |
| Submitting or waiting for upload | Transfer in progress; keep the dialog open |
| Upload succeeded | Your report and diagnostic package have been received |
| Upload failed | Click **Retry** and check the updated status |
| Some attachments were not collected or sent | Review which files were skipped and recollect if needed |
| Upload unavailable | Save the ticket ID and use the fallback report and contact options |

Wait until the status shows **Upload succeeded** before closing the dialog so all diagnostic attachments finish transferring.

## If submission fails

Check your network connection and click **Retry**. If direct upload remains unavailable, copy the fallback report text and share it with the maintainers alongside your ticket ID and reproduction steps. Fallback options such as system mail or QQ Mail are used only when direct submission fails.

If the original task was closed, replaced by a new session, or missing key files, reopen the project, trigger the issue again, and collect a fresh report.

To report typos, missing screenshots, or suggestions for this documentation, visit the [Wiki feedback page](../../../project/wiki-feedback/wiki-feedback.mdx). For software bugs, submit through **Report a bug** inside Lumina so diagnostic data is included.
