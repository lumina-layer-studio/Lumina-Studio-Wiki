# What Should I Check When Lumina Will Not Open, Keeps Spinning, or Fails to Generate?

When troubleshooting load or generation issues, start at the **earliest stage that behaves unexpectedly** and change one variable at a time so you can pinpoint the exact cause.

Every session moves through six stages: **open Lumina → connect to the backend → prepare a minimal input → complete a minimal Preview → Generate → download, open, or report**. Resolving an upstream blocker restores everything downstream.

## Four ground rules before you start

- **Let active tasks finish**: wait for a spinning **Preview** or **Generate** job to complete or return an error rather than clicking repeatedly.
- **Capture the error before clearing state**: save the first complete error message before running **Clear Cache**.
- **Use genuine exported files**: renaming an unsupported file to `.png` leaves incompatible data inside and will still fail validation.
- **Protect private work**: strip personal details, credentials, and unreleased commercial artwork before posting screenshots or files in public channels.

## Six-step diagnostic sequence

/>

### Step 1: Confirm the application loads completely

If the browser shows an error page, a blank screen, or never renders the Lumina Studio workspace, focus on the entry point first:

1. Verify you are opening the current official URL or standard local launcher rather than an outdated bookmark, temporary link, or dev port.
2. Refresh the page once to see whether the symptom persists.
3. Test the same URL from another network (such as a mobile hotspot) or a second device at the same time.
4. Note the time, region, and connection type.

When only a single device fails, check browser extensions, VPN/proxy rules, or local firewall settings on that machine; when multiple devices and networks fail simultaneously, retry shortly or report a service outage.

### Step 2: Check the backend status in the top bar

Seeing **Checking backend...** briefly on launch is normal and should transition to **Backend connected** within a few seconds.

If the header stays on **Backend unreachable**:

- **Online edition**: note the timestamp and network, then retry shortly or submit a report.
- **Local edition**: restart Lumina Studio via its standard launcher and reload the page.

Uploads, **Preview**, and **Generate** all run through the backend service, so wait until **Backend connected** appears before testing files.

### Step 3: Separate file issues from environment issues

Test with a small, clean JPG or PNG alongside a Material Archive or Classic LUT you know works. Turn off Batch processing, Large Format Mode, and optional hardware add-ons so only core conversion settings remain, and verify that:

- Upload completed fully (a thumbnail appears, not just a filename).
- **Source Type** and the required archive, brand, or LUT are selected.
- Image dimensions, color channels, and PNG alpha transparency look normal.
- If testing an SVG, no missing fonts, masks, filters, or out-of-bounds `viewBox` coordinates are blocking parsing—see [How Do I Fix SVG Upload Failures, White Backgrounds, Holes, or Missing Detail?](pathname:///en/docs/knowledge/svg-troubleshooting/).

If the simple test image previews cleanly while your original file fails, the issue lies in that file or parameter combination; if even the minimal image fails, continue checking the connection and app state.

### Step 4: Complete one minimal Preview

Using standard single-plate dimensions and default parameters, run a single **Preview** and wait for it to finish or display an error.

If **Preview** hangs or fails:

1. Check that the top bar still shows **Backend connected**.
2. Confirm both the artwork and color source are selected.
3. Turn off Large Format, Batch, Puzzle, and optional add-ons.
4. Run a comparison test with a small flat image and copy the full error message.

Once the minimal test succeeds, restore your original artwork, print dimensions, and advanced features one setting at a time until you find the exact option that triggers the failure.

### Step 5: Resolve a disabled or failing Generate button

Lumina unlocks **Generate** only after a **valid Preview** completes for your active settings. When **Generate** is grayed out, check in order:

- Both your input artwork and color source are loaded.
- You have completed a successful **Preview** with the current settings.
- You ran **Preview** again after changing the image, color source, or modeling parameters.
- Your active Modeling Mode, archive, add-ons, and export format are compatible.
- Finished dimensions, Bed Size, and Large Format settings show no blocking warnings.

If **Preview** succeeds yet **Generate** returns an error, copy the full message first, turn off optional add-ons, and test a minimal **Generate** run with your small sample image.

### Step 6: Separate download issues from slicer issues

Once **Generate** finishes, save the full `.3mf` or `.zip` file to disk before troubleshooting the slicer:

- **Download link missing or expired**: temporary session files were cleaned up—run **Preview** and **Generate** again and save the file right away.
- **Downloaded fine, one-click slicer launch failed**: verify **Slicer Software** and your custom app path in Settings, or open the file directly in your slicer—see [What If Lumina Cannot Find the Slicer or Open the 3MF?](pathname:///en/docs/knowledge/slicer-path-and-open-troubleshooting/).
- **Opens in the slicer with wrong colors**: check object, project-filament, physical-spool, and AMS-slot assignments—see [Open a Lumina 3MF in Your Slicer](pathname:///en/docs/tutorials/slicer-material-mapping/) and [Why Do Lumina Preview, Slicer Preview, and the Physical Print Look Different?](pathname:///en/docs/knowledge/preview-slicer-print-differences/).
- **Large Format or Batch `.zip` archive**: extract the entire ZIP to a folder on disk before opening the `.3mf` files inside.

## When to use Clear Cache

Use **Clear Cache** on a local installation only when temporary session, Preview, or download state becomes stuck and neither restarting the app nor running a minimal test clears it:

- Clearing cache invalidates active temporary previews and download links, so you will re-upload, **Preview**, and **Generate** afterward.
- Your saved Material Library archives and configuration presets remain untouched.
- File-format errors, incompatible parameters, and slicer slot mappings are unaffected by cache clearing.

## Decoding common error messages

You do not need to memorize numeric error codes—focus on what the message describes:

| Message meaning | Typical cause | Recommended action |
| --- | --- | --- |
| Invalid input or missing required field | Unselected color source, incomplete settings, or unreadable file payload | Step back to the minimal baseline and fill in each required field |
| Unsupported file format | Internal file format mismatches its extension, or unsupported mode | Re-export a genuine JPG, PNG, SVG, WebP, or HEIC from your editor |
| File too large or complex | Oversized pixel dimensions or extreme SVG node count | Test a downscaled copy while keeping your master file safe |
| File or session not found | Temporary output expired, page refreshed, or session reset | Re-select your artwork, then run **Preview** and **Generate** |
| Too many active tasks | Rapid repeated clicks or another job still running | Wait for the current job to finish, then submit once |
| Service unavailable or timeout | Backend interruption, network drop, or heavy job timeout | Record the timestamp and error text, then retry with a small test image or report |

## Baseline minimal test checklist

Use this clean baseline whenever you want to verify core functionality:

1. Current official URL or standard local launcher
2. A small, clean JPG or PNG verified to open normally
3. A previously working Material Archive or Classic LUT
4. Standard finished dimensions and default parameters
5. Batch, Large Format, and optional add-ons turned off
6. One **Preview** run, followed by one **Generate** run once Preview completes

## Helpful details to include in a bug report

- Lumina Studio version and edition (online vs. local)
- Timestamp, region, and network type
- Exact stage where the workflow stopped and the first complete error message
- Step-by-step actions from opening Lumina
- Original input file, or a privacy-safe minimal sample that reproduces the bug
- Selected **Source Type**, archive or LUT name, **Modeling Mode**, print dimensions, and active options
- Relevant screenshots, plus the untouched `.3mf` or `.zip` if generation completed

When using **Report a bug** inside the app, expand **Automatically collected info** first to review the captured UI state, parameter selections, and diagnostic logs (screenshots are optional; never attach passwords, API keys, or confidential commercial files). If network issues block direct submission, copy the backup report text and share it via an official support channel.

## Common questions

### How long should “Checking backend...” stay visible?

Normally just a couple of seconds on initial load. If it hangs indefinitely or switches to **Backend unreachable**, troubleshoot the network or restart your local launcher before adjusting artwork settings.

### Generate stays grayed out—is that an account permission restriction?

No. **Generate** activates automatically once valid artwork, a color source, and an up-to-date **Preview** for your current settings are all in place. Changing the image, color source, or key modeling parameters invalidates the previous Preview—click **Preview** once more to unlock **Generate**.

### Why does Lumina open on my phone hotspot but not on home Wi-Fi?

That points to an ISP routing, local DNS, or proxy/firewall difference rather than an issue with your artwork or archives. Share both network details, the timestamp, and your region with the team rather than changing all browser and system settings at once.

### Will Clear Cache erase my custom Material Archives?

No. **Clear Cache** removes temporary session data, cached previews, and temporary outputs while preserving your user Material Library and saved presets.

### Why did my download button stop working after refreshing the browser?

Preview and generation outputs live inside a temporary session; refreshing the tab, timing out, or clearing cache releases old temporary links. Re-upload or reselect your artwork, run **Preview** and **Generate**, and save the `.3mf` directly to a local folder.

### Do I have to attach my private artwork when reporting a bug?

Not at all. Recreate the issue with a simple geometric PNG or SVG that shares the same file format and settings, attach that safe reproduction file, and note any differences from your original piece.
