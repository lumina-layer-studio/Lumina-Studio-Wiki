# 反馈问题与诊断信息

遇到生成失败、预览异常或操作结果不符合预期时，可从顶栏打开“反馈问题”。软件会自动打包当前任务的诊断信息，点击发送即可直接提交至官方问题收集服务，无需配置个人发件邮箱。

## 先复现问题，再打开反馈窗口

请保留触发问题的图片、配方与参数设置，在刚复现问题后立即打开反馈窗口，以便准确捕获当时的运行上下文。若打开窗口后又更换了素材或重新执行过操作，请点击窗口内的重新收集按钮刷新诊断资料。

建议在问题描述中写明：

1. 输入格式与颜色来源（例如 SVG + 耗材档案）。
2. 具体操作顺序，以及从哪一步开始出现异常。
3. 预期效果与实际现象的差异。
4. 该问题是每次必现，还是仅出现在特定文件上。

联系邮箱为选填项，便于维护者跟进回复；还可额外上传 PNG、JPG、WebP 或 GIF 截图（如文件格式或大小不符，请按窗口提示调整）。

## 自动附带的诊断资料

诊断包会根据当前任务收集转换参数、设备选择、近期操作记录、错误日志，以及当前会话中可用的原图、SVG、模型、LUT、耗材档案与导出结果。具体包含哪些文件，取决于当前会话实际已载入和生成的内容。

这些附件用于帮助开发者复现并定位问题。发送前请留意窗口中的上下文与附件清单，确认其中不包含不宜外发的客户稿件或受限模型，同时检查截图是否带有账号、通知等个人隐私信息。

## 查看工单编号与上传状态

点击提交后，请记录生成的工单编号，并留意窗口中的最终上传状态：

| 界面状态 | 含义与后续操作 |
| --- | --- |
| 正在提交或等待上传 | 诊断包仍在传输中，请稍候 |
| 上传成功 | 诊断包已完整提交至问题收集服务 |
| 上传失败 | 点击“重试”重新上传，并留意最新状态 |
| 附件未完整收集或部分附件未发送 | 按提示核对缺失文件，必要时重新收集 |
| 上传不可用 | 保留工单编号，改用窗口提供的备用报告与联系渠道 |

请等待状态变为“上传成功”后再关闭窗口，以确保诊断附件完整送达。

## 提交失败时的处理方法

若上传失败，请先检查网络连接并点击“重试”；若多次重试仍未成功，可复制窗口生成的备用报告文本，连同工单编号与复现步骤一并发送给维护者。系统邮件或 QQ 邮箱等备用入口仅在线上直传不可用时启用，日常正常提交无需预先配置。

若原图已关闭、会话已被新任务替换或关键文件未能成功收集，请重新打开对应任务触发一次问题，再重新收集并提交完整报告。

如欲反馈文档错漏、配图缺失或排版建议，请前往 [Wiki 反馈页](../../../project/wiki-feedback/wiki-feedback.mdx)；软件功能故障请优先使用软件内的“反馈问题”入口，以便同步附带诊断上下文。
