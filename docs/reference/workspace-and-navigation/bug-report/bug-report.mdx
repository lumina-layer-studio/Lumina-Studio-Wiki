# 反馈问题与诊断信息

顶栏的“反馈问题”用于把可复现的问题交给 Lumina 开发者。它会把用户描述与当前软件上下文放在同一张
工单中，减少来回询问版本、模式和最近操作的次数。

## 需要填写的内容

- **问题描述：** 必填，最多 10,000 个字符；
- **联系邮箱：** 可选，最多 320 个字符；
- **截图：** 可选，支持 PNG、JPEG、WebP 和 GIF，文件不能超过 5 MB。

描述中应写清楚预期结果、实际结果和可以重复问题的操作顺序。若问题只在某个图片、LUT、耗材档案或
3MF 上发生，不要默认公开原文件；先说明现象，等开发者确认需要哪些最小素材。

## 自动上下文

反馈窗口打开时会采集一次当前上下文。摘要直接显示：

- 当前页面；
- 当前色彩模式；
- 当前 LUT；
- 最近 3 次操作；
- 最近 2 条 API 错误。

“完整上下文”只有在用户展开后才会序列化，用于检查更完整的参数、动作和日志。填写描述不会持续重复采集，
因此需要记录最新操作时，应先完成复现，再打开反馈窗口。

## 路径和技术错误的处理

备用报告文本会替换常见的本机路径、`file://` 地址、Windows/UNC 路径和堆栈帧，并把只有 HTTP 状态码的
错误转换为可读提示。这能减少无意带出本机目录的风险，但不能代替用户检查：

- 描述框中的文字由用户直接填写，不会替用户改写；
- 手动附加的截图可能包含文件名、账号、通知或其他个人信息；
- 原图、客户素材和未公开设计不应在未确认授权时上传。

提交前先展开上下文并检查截图。需要隐藏的内容应先在截图工具中处理，而不是依赖发送后删除。

## 提交结果与备用发送

提交成功后会返回工单编号，并显示邮件是已发送、等待发送、发送失败还是服务器未配置邮件。邮件失败或未配置
时，只有在当前环境提供中继功能且用户明确选择发送后，软件才会尝试中继。

如果自动提交失败，窗口会生成可复制的备用报告，并提供系统邮件或 QQ 邮箱入口。备用文本仍应在发送前
检查一遍；工单编号和复制文本可以用来继续与开发者沟通。
